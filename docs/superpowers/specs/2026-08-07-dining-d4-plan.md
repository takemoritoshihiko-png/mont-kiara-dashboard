# D4: 外食モード 実装計画

作成: 2026-08-07 ／ 状態: 骨格（v9全機能棚卸しの結果で詳細確定）／ 前提: D3(飲食レイヤー)マージ後に着手

## ゴール

台帳v9の個人記録機能を新アプリに移植し、必須要件6つを完成させる。
①訪問したか ②また訪問したいか ③1人あたり予算 ④感想 ⑤訪問済み一覧 ⑥カテゴリで選べる（⑥はD3で完成）。

## 設計の柱

### モード切替
- ヘッダーに「住まい / 外食」の2値トグル。外食モード = 飲食層に固定 + 個人記録UIが出現。
- 住まいモードには個人記録を一切出さない（公開サイト用途との分離）。
- URL: `?mode=dining` を deep link に追加（layer と同様に復元）。

### 個人記録（localStorage）
- キー: `mkd_dining_personal_v1`。形: `{ [restaurantId]: { v, rv, amt, m } }`（v9のST構造を継承: v=訪問済/rv=a・m・n/amt=実額RM/m=感想）。
- **感想 m は複数行 textarea に拡張**（v9は1行input。必須要件④）。
- v9からの持ち込み: v9のSTは placeId キー。インポート時に placeId→R#### へ変換するマッパーを用意（v9のDataタブJSONをそのまま食える形式に）。
- エクスポート/インポート/全削除。UIに「記録はこのブラウザにのみ保存され、他人には見えません」を明記。
- 書き込みは state.js セッター経由 + storage モジュール1本（`src/data/personal.js` 予定）。

### 訪問済み一覧（v9 Logタブ継承）
- 再訪意向（また行く/機会があれば/もういい）でグループ化。
- ヘッダーに実額平均などの集計（v9の計算式をそのまま移植 — 棚卸し結果で確定）。

### スコア表示の継承
- v9の縮約★（レビュー母数で信頼度補正した評価）と「レビュー母数の厚さ」表示を継承。
- 計算式は棚卸しで正確に書き出し、`src/domain/` の純関数 + テストで固定する。

### やらないこと（YAGNI・統合プラン踏襲）
- 多端末同期・予約API・写真・営業時間の構造化。

## テスト計画
