# 飲食の目的再定義と「推奨軸」設計 — 検討経緯メモ

> 鮮度: 現行有効（設計判断の根拠記録・2026-08-08）
> 竹森氏の指示「どういう筋道でその結論を出したのか、プロセスをアプリの中で経緯としてメモしておく」に基づく。

## 0. 何が問われたか（経緯）

1. 2026-08-08、外部意見書「KL飲食店インテリジェンス設計書」を受領。骨子=①ミシュランKL版は構造的に偏る（セランゴール圏外・マレー料理僅少・屋台ゼロ・鮮度問題）②統合スコアを作るな、独立ソースの一致を数えろ③判断は家族のログにしかない。
2. 竹森氏の目的定義: **「飲食の美味しいお店だけをピンポイントで行くアプリ」**。
3. 補足裁定: **ミシュランは完全網羅のままでよい。ただし別軸で「本当に美味しい」が推奨されれば100点**。
4. AIの初回提案（68点）と再提案（88点）は、①既存台帳の鮮度劣化対策の欠落 ②「金曜の夜どこ行く」場面への最適化不足 を自己指摘して作り直した。本メモはその最終検討の記録。

## 1. ゼロベースの気づき: 網羅とピンポイントはベクトルが逆

- 完全網羅 = recall最適化（取りこぼしゼロ）。2026-08-08朝に完了（現存する公式KLミシュラン75店を全収載）。
- 「美味しい店だけ」= precision最適化（ハズレゼロ）。**網羅の達成が自動的にピンポイントを壊す**: 網羅ゆえに Li Yen(★3.9)や Café Café(★4.1)のような「掲載はされているが群衆評価が弱い」店も台帳に入った。
- 解決 = **データは網羅、表示レンズは2枚**。台帳レンズ（全店・索引）と推奨レンズ（本当に美味しい確証がある店だけ）を分ける。データを消さずに目的を両立する。

## 2. 実測した事実（このメモの根拠データ）

### 2-1. 台帳114店の確信度分布（2026-08-08実測）
- 二重確証（ミシュラン/Tatler × Google★4.4×300+）: **36店**
- 権威単独: 23店 / 群衆単独: 29店
- **乖離（権威あり×Google4.3未満）: 15店** — ただし内訳が本質:
  - 老舗・ホーカー系8店（Wong Mei Kee 3.8×2903 等）= Googleの低さは行列・接客・雰囲気への不満が主で、美味しさの否定ではない可能性（意見書3-3の「大衆↓専門↑=通好み」パターン）
  - 高級系7店（Li Yen 3.9、Café Café 4.1、Shanghai 4.1 等）= 同業態の期待値では異常に低い=本当の要注意候補
  - **Dewakan(2★)ですら4.2** — 前衛ファインダイニングも大衆評価が構造的に伸びない。単純な足切りは国内最高峰を切り落とす
- 評価値なし（null契約）: 6店 / 閉店: 1店（Heun Kee）

### 2-2. ティア規則を実データに当てた結果（機械判定の限界）
試作した機械規則では Dewakan が「要注意」、Sek Yuen(1948年創業)が「高級」に誤分類された。
→ **乖離の「存在」は機械が検知し、乖離の「解釈」（通好み/要注意）は根拠つきの人裁定フィールドに持つ**。数値合成をしない原則とも整合。

### 2-3. 独立ソース44店の相互重複=ゼロ（検証C・2026-08-08）
Eat Drink KL / Malay Mail / Time Out / TastyJournal / Bangsar Babe の2025-26年推薦44店に、**2ソース以上が重複して推す店が1つも無かった**。
→ 意見書3-2の「独立クラスタの一致」は、ミシュラン×Tatler×50Bestが実際に重複するファインダイニング層では機能するが、**ローカル食堂層では構造的に機能しない**（各媒体が別々の街区を見ている）。
→ ローカル層の推奨昇格は「外部の合意」では作れず、**候補箱→家族が実食→判定**の一本道しかない。意見書5-2の結論が実証された。
- 副産物: 閉店扱いにした Heun Kee が Cheras(Taman Connaught)で2026-06に推薦されている=移転の可能性（要検証）。D7で2次ソース待ちだった Grumpy Bagels に TastyJournal の推薦が付いた。

### 2-4. 権威リストの実物照合（検証B・2026-08-08）
- Asia's 50 Best Bars 2026 のKL勢6店（Three X Co 32位/Bar Trigona 38/Reka 63/Penrose 64/Cabinet 8 65/Coley 83）を公式で全数確認=意見書の数値と完全一致。選考はDeloitte監査+利益相反規則あり=**独立性最高クラス**。
- Tatler Best Malaysia 2026: レストラン17/20・バー17/20+Best-in-Class実物を取得（残3はサイト側の切断で取得不能と正直に記録）。**2026年から順位制になった初年度**で、選考手続の開示は50 Bestより軽い=独立性は一段落ちる扱いが妥当。
- 台帳との重複: Tatler 2026レストランのKL/PJ勢のうち15店が既収載=推奨軸の相互確証に使える。

### 2-5. 「金曜の夜」タスク歩行（実画面・2026-08-08）
子連れ◎×30分圏×RM50-150 の組み立てに**4タップ**（子連れトグルが折りたたみ内）、結果21店=実用的な候補プール。プリセット1タップ化の価値を確認。

## 3. 結論（推奨軸の設計）

1. **台帳=網羅（現状維持）**: ミシュラン全掲載+群衆枠。消さない。索引・資産。
2. **推奨=別軸のカテゴリバッジ（数値合成しない）**:
   - 🥇 **鉄板**: 家族が「また行く」= 最上位。外部が何と言おうと家族の判定が勝つ
   - ✅ **二重確証**: 独立の権威（ミシュラン/Tatler/50 Best）×群衆強シグナルが一致（36店）
   - 🎖 権威単独 / 👍 群衆単独
   - 🤔 **通好み**: 乖離あり・老舗大衆系（低評価の主因が味以外と裁定済み）
   - ⚠️ **要注意**: 乖離あり・裁定でも説明がつかない（推奨レンズから除外）
   - ⬜ 未確証（評価値なし）/ 🚫 閉店・休業（推奨レンズから自動除外）
   - 乖離8+疑問4店の裁定材料は検証Aの実勢調査による（本メモ末尾に結果を追記）
3. **家族の記録が唯一の「判断」**: 「もういい」= 外部評価に関わらず推奨から外す（家族拒否権）。
4. **鮮度の守り**: verified(最終確認日)+四半期の生存スイープ+12ヶ月言及なしチップ。閉店店の轍（Qureshi問題）を自分が踏まない。
5. **ローカル層の拡張**: 検証Cの44店級は「候補箱」（台帳外の軽いリスト）へ。昇格は家族実食のみ。
6. バー6店（50 Best）は別途裁定（10分類目 or 別レイヤー）。

## 4. 棄却した代替案と理由

- **統合スコアに推奨を織り込む**: 「どの質問にも答えない数字」になる（意見書3-1）。棄却。
- **Google値の足切りで推奨を作る**: Dewakan・老舗ホーカーを誤殺する（2-1実測）。棄却。
- **独立2クラスタ一致を推奨の必要条件にする**: ローカル層で重複ゼロの実測（2-3）により、ファインダイニング専用の物差しと判明。限定採用。
- **FSQ OS Places導入・L0マスタ**: 数百店規模ではrestaurants.jsonが既にマスタ。過剰装備。棄却。
- **家族4人別々の★**: 共有1ファイル運用が始まったばかり。スマホ運用開始時に再検討。保留。

## 5. 検証Aの結果（乖離店の実勢・2026-08-08帰還）と裁定案

直近12ヶ月のレビュー原文・専門筋の掲載継続を突合した結論:

| 店 | 低評価の真因（実勢） | 裁定案 |
|---|---|---|
| Dewakan(2★・4.2) | 価格期待値ギャップ+挑戦的な味+会計等フロント細部。**料理劣化なし・専門筋の支持は最も強固** | 🤔通好み（高額・挑戦的。万人向けでないと明記） |
| Li Yen(3.9) | 祝祭限定ビュッフェの品質ブレが低評価を集中生成。通常の点心・アラカルトは高評価(TA4.5) | 🤔通好み（条件: 祝祭ビュッフェを避ける） |
| Shanghai Restaurant(4.1) | ホテル価格vs一般客の価格感覚。劣化兆候なし・2026/2「人生最高の小籠包」 | 🤔通好み（価格覚悟） |
| Passage Thru India(4.3/TA4.0) | 団体ツアー流入時の待ち・ブレ。個人客のアラカルトは常連が支持継続 | 🤔通好み（条件: 団体時間帯を避ける） |
| Wong Mei Kee(3.8×2903) | **味でなく供給構造**（1日3時間営業に需要集中・支払い20分/提供40分待ち）。「変わらず美味しい」が多数派 | 🤔通好み（条件: 開店直後に行く） |
| Sek Yuen(4.1) | ノンエアコン+2026年初頭に単発の調理ブレ。老舗の味は維持が多数派 | 🤔通好み |
| Sri Nirwana Maju(4.1) | 混雑・駐車の構造不満（Wong Mei Kee同型）。ただし一次レビューの裏取り薄 | 🤔通好み（暫定・次回スイープで再確認） |
| Café Café(4.1) | **データ不足**（レビュー投稿頻度自体が低い店。直近一次情報を取得できず） | ⬜未確証扱い（推奨レンズから外す・次回スイープで再調査） |
| Congkak / Lama Nyonya / 他bib系 | Lamaは移転直後で評価母数リセット中 | 🤔通好み暫定 / Lamaは移転後6ヶ月観察 |

**パターン結論**: 「権威×群衆の乖離」の実勢は (a)高級系=価格期待値+祝祭/団体運営ブレ (b)老舗大衆系=ミシュラン後の需要に供給が未対応、のどちらかで、**味の劣化が確認されたケースはゼロ**。⚠️要注意ティアは「裁定しても説明がつかない店」専用の空集合スタートとなる。これは規則が甘いのではなく、実勢調査が全店に説明を与えた結果である（将来の生存スイープで説明のつかない劣化が出たら初めて⚠️が入る）。

## 6. 実装への落とし込み（次の実装バッチの仕様）

- スキーマ: `rec`(推奨ティアenum: teppan/double/authority/crowd/tsuu/caution/unverified/closed は表示時導出とし、**保存するのは導出に必要な素材のみ**=`recDivergence`(裁定: 'tsuu'|'caution'+根拠1行`recNote`)・`verified`(最終確認日)・`closed`(bool)。鉄板/二重確証等は既存データ+家族記録から純関数で導出=二重管理を作らない
- 推奨レンズ: 外食モードに「⭐ 推奨」フィルタチップ(既定ON案は裁定待ち)。除外=⚠️/⬜/🚫/家族「もういい」
- 「今夜どこ行く」プリセット(1タップ): 推奨×子連れ◎×〜30分×中価格以下
- 権威バッジ: Tatler 2026(17/20実物)・50 Best Bars 6店(全数照合済)を`awards`に手入力。バーの層は裁定待ち
- 候補箱: 検証Cの44店(相互重複ゼロ層)を docs/dining-candidates-box.md に記録。昇格=家族実食のみ
- 生存スイープ: 四半期定例(生存+言及+候補箱+ソース死活)。初回でCafé Café/Sri Nirwana再調査とHeun Kee移転疑い(Cheras Taman Connaught)を検証

## 8. 裁定変更(2026-08-08夜・竹森氏)

- **⭐推奨レンズ(既定絞り込み)と🌙今夜どこ行くプリセットは撤去**。「絞り込みは自分で状況を見ながら考える」ため、機械による既定の間引きは不要との裁定。
- **推奨バッジ(鉄板/二重確証/通好み等)と裁定データ(recDivergence/recNote)・recommend.jsは存続** — カード/詳細に理由つきで表示され続ける。判断材料の提示までがアプリの仕事で、間引きはしない、という整理。
- 同夜、一覧の密度を全面改善: カード307px→190px(スコア1行化・住所行を詳細送り・評価+記録ボタン1行化・小型ボタン)、可視カード1.08→2.39枚。チップ整列も修正。

## 9. UI改定第2弾(2026-08-08夜・竹森氏指示)

- **選択=その店へ寄る**: 旧「選択は地図を動かさない」契約を改定。一覧/地図で店を選ぶと DETAIL_ZOOM(17=店名ラベルが常時出るズーム)まで寄り、選択ピンは1.45倍+アクセントリング+波紋パルスで「この店」と指させる
- **外食の3タブ(台帳/行った店/データ)を廃止**: データ=保存バー右の「💾データ管理」入口+ビュー内「←台帳にもどる」。行った店=「自分の記録」トグル列の「✓行った店」チェックが代替(集計タイル・rv別グループ表示は廃止。純関数diningLog.jsはテスト付きで保持)。タブ列撤去でヘッダ223→198px

### §9補足(同日・条件値の確定)
選択ズームをさらに改定: **選択=必ず中心+常に FOCUS_ZOOM(=CLUSTER_OFF_ZOOM=16) の1ルール**。16は「クラスタの数字玉が解けて全店が個別ピンになる、いちばん引いた縮尺」。17は寄りすぎ・15は数字玉に混ざる、という竹森氏の条件値を定数で固定(panInside方式は中心に来ないことがあるため全廃)。実測=選択ピンが中心から1px・ズーム16。
