## 2. 個人記録（ST）

### フィールド（`ST[placeId]`）
| キー | 値 | 意味 |
|---|---|---|
| w | 1/0 | 行きたい |
| v | 1/0 | 訪問済み |
| vd | "YYYY-MM-DD" | 訪問日。**v=1にした瞬間に自動記録**（既値は上書きしない）。UI編集不可 |
| rv | "a"/"m"/"n"/null | また行く/機会があれば/もういい |
| m | string | 一言メモ（1行input） |
| amt | string | 実額RM/人 |

保存キー: `kl_ledger_v5`（v5から引き継ぎ）。保存先は **window.storage（Artifact API・async）**。値はJSON.stringify(ST)1本。

### 保存挙動
- ボタン=即flush / 文字入力=250msデバウンス。saving/dirty再入ガード。
- pagehide/beforeunload/visibilitychange:hidden で flushSync。
- 成功「保存済み」+時刻(ja-JP 2桁時分秒)。失敗=赤バー+「データタブから書き出して控えて」。
- **起動時に空書込テストで保存可否を確定**（読めても書けない環境の初回検出）。

### 操作の正確な挙動
- 行きたい: w反転→即保存→全再描画→toast
- 訪問済みON: v=1 **かつ w=0（自動解除）**、vd未設定なら今日→visitbox出現→toast「また行きたいか答えてください」
- 訪問済みOFF: vのみ0。**rv/m/amt/vdは残る**（再ONで復活）
- 再訪3択: 同ボタン再押下でnull（未回答）へ
- メモ: デバウンス保存・再描画なし（フォーカス維持）
- 実額: デバウンス保存＋**counts()だけ即時更新**（タイプ中にヘッダー平均が動く）
- 訪問済カード: `.visited`＝opacity .55（一覧で沈む）
- visitboxは台帳カードとLog行の**両方**にあり、Logからも直接編集できる

### 集計式（コードそのまま）
- ヘッダー（母集団=全50件）: cWant=Σw / cVisit=Σv / cAmt=amt>0の平均をround（無ければ—）/ cBase=C.toFixed(2)=4.36
- Log（母集団=訪問済のみ）: タイル=[訪問数][また行く数][平均実額=round(Σ/n)][記録した支出=Σ.toLocaleString()]
- データタブ: 記録中：訪問X／行きたいY／一言メモZ（m.trim()非空）／実額W
- ⚠ヘッダー平均とLog平均は**母集団が違う**（欠陥3と連動）

## 3. スコア式（縮約★）

```
YEN=35（1RM=35円）  M=800（ベイズ事前重み）
C = Σ(r×c)/Σ(c) = 4.3600（件数加重平均）

au = MI[m].v (2star:35/1star:29/bib:21/sel:16/none:8)
   + exタグごとに排他if: "Best 20"→+4 / "Best-in-Class"or"Award"→+2 / "国際評価"→+3
   → min(35, au)
ct = TIER[t].v (4:25/3:19/2:12/1:6/0:0)
rb = (c×r + 800×C)/(c+800)              ← 縮約後★
ev = 40 × clamp((rb−3.90)/0.80, 0, 1)   ← 3.90=0点・4.70+=満点
total = round(au+ct+ev)
pk = dH || lH（価格代表値=夜上限、無ければ昼上限）
hay = (n+j+cat+v+ar+ad).toLowerCase()   ← 検索対象
```

実データのexタグは5種のみ: 国際評価+3/Tatler Best 20+4/Tatler Best-in-Class+2/2026 Service Award+2/屋号は要確認+0。**文字列部分一致依存→移植時はenum化+テスト固定**。

表示: カード左列に total大数字+`au+ct+ev`内訳+3本バー(権威#A94A38 au/35・継続性#123B35 ct/25・評価#C4901F ev/40)。meta行=`Google ★r / c件（母数 厚い≥3000/標準≥1000/やや薄い≥300/薄い）→ 縮約後 rb`。既定ソート=total降順。内訳の二重丸め（round(ev)個別 vs round(合計)）は現50件で全件一致を検証済み。

## 9. 移植前に潰すv9の欠陥

1. **訪問日がUTC**（toISOString）→ MYT 0:00-8:00に押すと前日になる。ローカル日付で記録する。
2. **S()が読むだけで書く**（`ST[i] || (ST[i]={})`）→ 描画だけで空{}が50件生える。読み取り専用ゲッターと分離。
3. **訪問済OFFで隠れデータ残存** → ヘッダー実額平均だけが数え続けLogと食い違う。母集団の定義を統一（要設計判断: 実額平均は「訪問済み店のみ」に一本化が自然）。
4. **条件フラグ単一選択** → D5で解消。
5. 内訳の二重丸め → 表示も `round(total)−(au+ct)` 等で整合させるかテストで監視。
6. インポートのキー未検証 → 未知キー件数を表示。
7. 「エリア19分類」の本文記述 ↔ 実データ20エリア → 文言をデータ生成に。
8. HTMLエスケープ片手落ち → テンプレートエスケープ統一。
