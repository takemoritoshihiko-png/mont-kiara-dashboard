## 2026-08-07 (B3c 学費くらべ＋磨き)

**解消した既存項目**（上のB1・B3a-2で記録したもの）
- ✅ **School Finder の近隣物件クリックの挙動が不自然**: `sfActive=false;toggleSchoolFinder()` のインライン代入を廃止し、`sfSelectCondo()`（パネルを閉じる→層を物件に切替→選択）に置換。`window.sfActive` アクセサも削除。開いた瞬間にペナン全景へ飛ぶ `map.setView` も撤去（KL校を含むようになったため、飛ぶ先が存在しない）。
- ✅ **School Finder の「3km以内のコンド」を nearby() に載せ替え**: 独自 haversine を撤去し、詳細パネルの周辺タブと同じエンジンへ。バケットは 800m / 2km / 3km（通学圏に合わせて外周だけ 6km→3km）。「近い」の定義がアプリ内で一つになった。

**今回スコープ外にしたもの**
- **学費チャート（SVG曲線）はペナン9校のまま**: 曲線を引くには3〜17歳の全年齢に値が要るが、KL23校の公表は代表学年のみ（例: ISKL は Prep Reception / Prep Senior / Grade 6 / Grade 12 の4点）。曲線を作ると点と点の間を捏造することになるため、KL校は一覧（実額＋学年ラベル）だけで扱う。タイトルも「ペナン9校・年齢別」に改めて誤認を防止済み。KL側を出すなら「点だけを打つ散布図」が候補。
- **`SF_FEES`（inline.js の年齢別テーブル）と `schools_detail.json` が二重管理**: チャートは前者、一覧は後者を読む。全15年齢×ペナン9校を突き合わせた結果、食い違いは **2点だけ**（Fairview ペナン校の6歳＝20,000 vs 25,000、8歳＝25,000 vs 32,000）。原因は SF_FEES が PYP の学年を1年ずらして埋めていたこと。学校自身が `PYP 1 (Year 1)` と書いている以上 PYP N＝Year N が正なので、一覧側（公表実額）が正しい。チャートを廃止するか SF_FEES を実額に揃えるかは要裁定。
- **年齢セレクトは3〜17歳のまま**: schools_data.csv の age_range は18まであるが、学年ラダーが Year 13 / Grade 12＝17歳で終わるため。18歳（大学準備年の一部）を足すかは要裁定。
- **Prep Senior / Kindergarten 1 など就学前ラベルの学年対応は「ラベルの字面どおり」**: K1=4歳・K2/K3=5歳・Prep Senior=5歳と解釈した。学校ごとに実際の対象年齢が半年〜1年ずれる可能性はあるが、ずれた場合も「※近い学年 〇〇 の実額」と明示されるため嘘の数字にはならない。各校サイトでの裏取りはデータ精度トラック。
- **DOMレベルの回帰テストは今回も未整備**: fees.js は純関数として test/fees.test.js（45件）でカバーし、実データ33校に対する「公表されていない数字を返さない」不変条件も検証済み。ただし「学費くらべを開く→年齢を変える→行をクリック」の結線は実画面確認（Chrome, localhost:5205）に依存。

## 2026-08-07 (B4 仕上げ: a11y・モバイル・OGP・資料整合)

**解消した既存項目**
- ✅ **匿名ボタンの解消**: 「押せるのに名前が無い」要素を全て潰した。カード・周辺行・学費くらべ行は `role="button" tabindex="0" aria-label`、パネル開閉ボタン（中身が `&#9664;` の矢印だけ＝名前ゼロ）と凡例に aria-label、地図マーカーとクラスタの divIcon にも aria-label。test/a11y.test.js が「visible text か aria-label のどちらかを全 button が持つ」を回帰として押さえる。
- ✅ **モバイルの高さが header 分だけはみ出していた**: `#map:73vh + .panel:27vh = 100vh` を、高さが `calc(100vh - 52px)` の `.main` の中に置いていたため、パネル下端がちょうどヘッダー高さ分クリップされていた。`.main` 自体の高さを `calc(100dvh - 44px)` に直し、分割を vh でなく flex の割合（パネル 45%・地図が残り）に変更。

**今回スコープ外にしたもの**
- **og:image は作っていない**: リポジトリにスクリーンショット資産が無く、それらしい画像を生成すると「このアプリではない何かの絵」を配ることになる。`twitter:card` は `summary`（画像なしカード）。OGP画像を出すなら、実画面のスクリーンショットを資産として commit してから。
- **地図マーカーのキーボード操作は実装していない**: Leaflet のマーカーは地理順に並んだ絶対配置 div で、Tab で辿ると地図上をランダムに飛び回る（最大392個）。同じレコードを意味のある順序で持つ一覧が代替経路になっており、`#map` の aria-label もそこへ誘導している。方針は src/ui/a11y.js の冒頭コメントに明記済み。マーカー個別のフォーカスが要るなら、Leaflet の keyboard plugin か「表示中マーカーだけを roving tabindex で辿る」独自実装が必要。
- **検索欄には aria-label を足していない**: 既に `<label for="fSearch">検索 / Search</label>` が accessible name になっており、別文言の aria-label を足すと可視ラベルと読み上げ名が食い違う（WCAG 2.5.3 label-in-name 違反）。「全フォーム要素が label か aria-label のどちらかを持つ」ことは test/a11y.test.js が検査する。
- **エリアジャンプのボタンはモバイル 32px**: 40px にすると地図上のバーが2行になり、地図そのものを潰す。13個が横スクロールで詰まる構造のため、40px 化は「バーを折りたたむ / ドロップダウン化」とセットでないと成立しない。要裁定。
- **フィルタチップの ✕ は擬似要素で 40px の当たり判定を作っている**: グリフを 40px にするとチップがピルでなくなるため。隣のチップのラベル部分と当たり判定が数px重なる可能性がある（✕同士は重ならない）。実機で誤タップが出るならチップ間の gap を広げる。
- **DOMレベルの回帰テストは今回も未整備**: initA11y のキー処理は依存注入（`{doc, onEscape}`）で手書きスタブから直接叩いて検証したが、ランドマーク・aria・モバイルCSSは index.html をテキストとして読む契約テストであり、実際の描画・フォーカスリングの見え方は実画面確認に依存。
- **URLにフィルタ値を載せるかは未裁定のまま**（B3a-2 で B4 送りとした項目）: 今回は a11y・モバイル・資料が主題だったため触っていない。
